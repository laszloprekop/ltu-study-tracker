# Z0025E scan: everything with a time, a booking, a "before" or a group step

Scanned 2026-10-02 against `ltuedu.instructure.com`, course 614 (Z0025E Computer Networks), with a
student token, read-only. Extends `docs/canvas-data-map.md`; facts recorded there are not repeated.
Reproduce with:

```
node tools/scan/dump-course.mjs 614 <dir>             # modules, pages, assignments, discussions, announcements, groups, ...
node tools/scan/linked-files.mjs 614 <dir> --download # every file linked from those bodies, with lock state
```

The lab signup sheet is a Google Doc, read through the Google Drive connector. Lab activity text came
from the `.pka` files decoded with `pt-activity-tools` (`node tools/pkacli.js decode`). Student names,
group membership and the sheet's Status column are left out on purpose.

## Entity kinds

### 1. Lecture session (Zoom)
- **Where:** Homepage "Important dates" table (front page, `GET /courses/614/front_page`). Weekly
  announcements repeat that week's sessions and name the lecture number.
- **Machine-readable?** Parseable. The table is a real HTML `<table>` with columns
  Date | Time | Activity | Location, e.g. `05 Oct | 09:00–10:30 | 🎓 Lecture | Zoom`. The lecture
  *number* is not in the table, only in announcements: `🎓 Monday, 28 September – Lecture 4 (09:00–10:30, Zoom).`
- **Count:** 13 lecture rows (plan.mjs already holds them).
- **Examples:** 17 Sep 14:30–16:00; 30 Sep 13:00–14:30 (Lecture 5, confirmed by the Week 3 announcement);
  10 Nov 09:00–10:30 (no lecture left to assign by module order).
- **Leads to:** the lecture page (`N.M Lecture K`). After a held lecture the teacher adds a
  "Lecture Recording" block to the page: 2.4 (updated 28 Sep) and 3.2 (updated 30 Sep) have one, no
  other lecture page does. So a page's `updated_at` landing on the session date is a signal that the
  session happened and a recording exists.
- **Prep:** none stated per lecture. Only the first lecture has explicit prep (welcome announcement:
  Pre-Knowledge module, 0.1, the checks).

### 2. Self-paced lecture (Discussion with a required post)
- **Where:** Discussion module items under the "Self-Paced Lectures" SubHeader: 1.4, 2.3, 3.4, 5.4.
- **Machine-readable?** Structured for existence (`require_initial_post: true`, `must_contribute`),
  but no date at all: `posted_at`, `lock_at`, `todo_date` are all null. Timing only comes from an
  announcement ("This week is a self-paced learning week", Week 2).
- **The post:** each ends with an "Answer the Following (by clicking reply)" block, a parseable marker.
  1.4: run a traceroute, post the output plus 5 answers. 2.3: open vs proprietary protocol, 4 short
  answers. 3.4: choose an application, argue TCP or UDP. 5.4: traceroute TTL/ICMP vs ping.
- **Leads to:** the module quiz (the overview pages say do the activities first) and the midterms
  (Knowledge Checks "form the basis of the question bank").

### 3. Lab assessment session (bookable, 15-minute slots)
- **Where:** Homepage table rows `💻 Lab N`; the signup sheet (see Booking below); each lab
  assignment's "Lab Presentation" section.
- **Machine-readable?** Session window: parseable from the Homepage table
  (`30 Oct | 10:00–12:00 | 💻 Lab 4 | Zoom`). Slot grid: parseable from the Google Doc, one table per lab,
  rows like `16 - 30 minutes (13:15) | Group N: ... | <status>`.
- **Count:** 5 sessions (Labs 2 to 6). Lab 1 has none: its assignment says "No Lab presentation for
  Lab 1. Make sure you have submitted the lab report."
- **Examples:** Lab 2, 2 Oct 13:00–15:00 (sheet: 9 slot rows, 8 claimed); Lab 4, 30 Oct 10:00–12:00
  (the only morning lab, consistent in table and sheet); Lab 6, 13 Nov 13:00–15:00.
- **Group size in a slot:** the whole group must attend ("All group members must be present", L00
  slides; "All group members should be prepared to contribute", 9.1). One slot is one group's
  15 minutes, the rest of the 2 hours is free for that student.
- **Depends on:** the group existing, the slot being claimed, the report being finished ("You should
  have the lab and report completed by the time of your assessment session").

### 4. Lab report hand-in
- **Where:** Assignments 9.4 to 9.10 (`online_upload`, assignment group "Labs").
- **Machine-readable?** `due_at` structured. Format rule is prose: "combine the report into one PDF",
  "Only one member of the group should submit".
- **Group fields:** Labs 2 to 6 use `group_category_id` 347 (the "Lab Group 1..10" set). Lab 1 uses
  category 345, which the student token cannot list, and `grade_group_students_individually: true`.
- **Examples:** Lab 1 due 25 Sep 23:59; Lab 2 due 2 Oct 23:59 (same day as its session); Lab 4 due
  30 Oct 23:59 CET (first deadline after the DST switch, stored as `22:59:59Z`, not `21:59:59Z`).
- **Leads to:** the lab session the same day (Labs 2 to 6: session and due date always coincide).

### 5. Lab activity (Packet Tracer `.pka` / Wireshark lab sheet)
- **Where:** file links inside each lab assignment description (see Lab question sources).
- **Machine-readable?** The files are fetchable one by one (`GET /courses/614/files/<id>` works even
  though the list endpoint is 403). Instructions are inside the `.pka` (`<INSTRUCTIONS>`, HTML pages).
- **Count:** 14 PTSkills activities, all PT 4.1 format; 2 Wireshark PDFs with 2 trace zips; 2
  separate description PDFs (PTSkills 11 and 13, "USE THIS FOR PTSKILLS N").
- **Depends on:** the software (`💻 Required Software`: install and test "before your first lab").

### 6. Module quiz
- Known: 8 `external_tool` assignments (New Quizzes), all due 2 Dec. Added: 2 attempts each
  (Assessments page; `allowed_attempts` on the assignment says -1, the real limit lives in the quiz
  engine, which the API does not expose). Pass rule 150/300 across the 8.
- **Prep (parseable):** every module overview ends with `💡 Before you take the Module N Quiz`; every
  end page with `Before moving on, make sure you have:` and `☐` lines naming the lectures, e.g.
  `☐ Completed Lecture 3: ...`, `☐ Completed the Module 2 Quiz`. 7 end pages, 5 or 6 `☐` each.

### 7. Midterm (24-hour window)
- **Where:** assignments 10.3 and 10.5, `unlock_at` and `lock_at` set (the only items with both).
- **Machine-readable?** Structured: 23 Oct 00:00 to 23:59, 20 Nov 00:00 to 23:59. Homepage says
  "All day | Zoom", though it is a Canvas quiz, individual, open book.
- **Prep:** 10.1, 10.2, 10.4 have `☐` checklists ("Reviewed the Module 1–4 Study Guides", "Attempted
  the relevant Knowledge Checks"). Study Guides are sections inside the module overview pages
  (`Study Guide` heading with `Focus question:` lines), not separate items.
- **Day Plan note:** the window is a day, not a slot; the student picks the hours.

### 8. Knowledge Checks and Check Your Understanding (formative, undated)
- **Where:** inside lecture pages and self-paced discussions. "Check Your Understanding" is embedded
  multiple choice (5 to 9 `Answer` reveals per lecture page). Knowledge Checks are external links to
  `gaia.cs.umass.edu/kurose_ross/knowledgechecks/problem.php?c=<chapter>&s=<section>` (80 links).
- **Leads to:** the midterm question bank (stated in 10.1 and 10.2) and the module quiz (L00: "MQ n
  are inspired from Chapter n online knowledge checks and problems").

### 9. Pre-knowledge poll (external form, 2 minutes)
- **Where:** Discussions 0.2 to 0.8, `[2min]` in the title (parseable duration). The poll itself is a
  Microsoft Form (`forms.cloud.microsoft` / `forms.office.com`), with a live results link; the Canvas
  requirement is a reply in the discussion.
- **Count:** 7, for Modules 2 to 8. There is no Module 1 poll although 0.1 says "for each of the eight".
- **Timing:** only the welcome announcement: "before the first lecture" (17 Sep).

### 10. Weekly announcement
- Known kind. Added shape: 3 so far (welcome 16 Sep, Week 2 21 Sep, Week 3 28 Sep), posted Monday
  morning (05:30 to 07:00 local), title `Welcome to Week N`. Body has a `Week N Outlook` list, one
  line per session, pattern `<emoji> <Weekday>, <D Month> – <Lecture K|Lab N> (<HH:MM>–<HH:MM>, Zoom).`
  and a `Reminders` list. It is the only source that ties a lecture number to a date, and the only
  place a booking deadline appears.

### 11. Lab group (Canvas group set)
- **Where:** `GET /courses/614/groups`: 10 groups "Lab Group 1" to "Lab Group 10", category 347,
  `join_level: invitation_only` (the teacher assigns; students cannot self-join through Canvas).
  `group_categories` is 403.
- **Shape:** 8 groups have members, 2 are empty. Group names on the signup sheet are free text
  ("Grupp 7", "Group 5"), not tied to the Canvas group, and the member counts of 3 of the 8 groups
  differ between Canvas and the sheet. So the sheet is not derived from Canvas.
- **Group decision:** the L00 slides say a named teaching assistant "will organize" groups; 9.1 says
  register your group members on the signup sheet. Every lab assignment also says "can be completed
  either individually or in a group of 3 or 4", while the Assessments page says labs are group work.

### 12. Support forums (no time)
- Discussions 3985 (course) and 3977 (labs). Many pages instead link a dead forum in the old Canvas
  instance (`canvas.ltu.se/courses/23566/discussion_topics/255098`, 18 pages and discussions).

### 13. Course self-evaluation survey
- Classic quiz 1138, `quiz_type: survey`, no due date, in no module. Probably opens at course end.

## Booking and sign-up

- **One sheet for all labs:** Google Doc `1S9Bi-W6wMoTd7FH7IqcS04B09B25Hml7PrTGBL33xuM`,
  "[Z0025E] Lab Signup Sheet", owned by the examiner, created 5 Sep. It holds the Zoom link (the same
  room as lectures, `66123226809`) and one numbered heading per lab: `Lab2 - Oct 2nd - 13:00pm`,
  `Lab3 - Oct 16th - 13:00am`, `Lab4 - Oct 30th - 10:00am`, `Lab5 - Nov 6th - 13:00pm`,
  `Lab6 - Nov 13th - 13:00pm`. No Lab 1 section (Lab 1 has no session).
- **Grid:** 3 columns: `Time` (`0 - 15 minutes (13:00)`), `Group # and Name (First name + Last Name)`,
  `Status (Green = Complete)`. Labs 3 to 6 have 8 rows (2 hours). Lab 2 has 9: the last row is 15:00,
  outside the 13:00–15:00 window. Parse the `(HH:MM)` in column 1, not the heading.
- **Claiming:** a group writes its number and members into a free row. No rule found anywhere about
  when booking opens or closes, first come first served, or how far ahead. The sheet already shows all
  future labs, so booking is open from the moment the sheet exists.
- **Who announces it:** the weekly announcement, e.g. Week 3: "Please remember to sign up for a lab
  assessment session in Canvas before Friday" (the session day). So the de facto deadline is "before
  the session", announced the Monday of that week. 9.1 and every lab assignment repeat
  "Signup with a time slot on the LAB SIGNUP SHEET", without a date.
- **Capacity:** 8 slots per session for 8 active groups. No slack: every group must get one of the 8.
- **Identity rule:** "use the same name entered in the signup sheet" when joining Zoom.
- **Status column:** the teacher colours it green when a group passes; the doc was last modified at
  the end of the Lab 2 session. That is per-group assessment state: never read it into the shared page.
- **Day Plan consequence:** a lab session is a 2-hour window in the Course Plan, plus a 15-minute
  Booking per group in the Personal Layer once claimed. Unbooked, it is Unplaced work due "before the
  session day". The tracker can read the slot grid from the Doc but must read only the row the
  Student says is theirs.

## Surprises and contradictions

1. **The course introduction slides are last year's.** `L00 Course Introduction.pdf` (1.2, linked as
   "the current course introduction") carries "Computer Network Schedule 2025": lectures weeks 41 to
   49, Midterm 1 14 Nov, Midterm 2 12 Dec, final deadline 22 Dec, "Passing threshold 150 points
   combined", groups of three. Canvas says 23 Oct, 20 Nov, quizzes due 2 Dec, 75 per midterm.
2. **"Check the Canvas calendar"** (Homepage, 9.1, "subscribe to the course calendar"), but the
   course still has 0 calendar events and 0 appointment groups. The Homepage table is the calendar.
3. **Lab 3 heading vs slots:** sheet heading `Oct 16th - 13:00am`, slots 09:00 to 10:45; Homepage
   says 13:00–15:00. One of them is wrong; ask before booking.
4. **Report "before the session" vs deadline 23:59.** 9.1: submit "before your scheduled lab
   assessment". The assignment `due_at` is 23:59 the same day, hours after the session.
5. **Week 3 announcement says sign up "in Canvas"**; the sheet is a Google Doc. Canvas has no
   appointment groups.
6. **Recordings come from old course 453.** The recording blocks on 2.4 and 3.2 embed Kaltura videos
   whose transcripts are files in course 453, so they may be a previous year's recording, not this
   session's.
7. **Two items numbered 3.4** (Lecture 7 discussion and the Module 3 Quiz). Module 2 lists 2.4 before
   2.3 and has no 2.2. A ref of `"3.4"` matches both.
8. **Completion rules that cannot be met:** 5.2 (a Page) requires `must_contribute`; 5.3 has no rule.
9. **Lab 3's "Lab Files" list links locked copies** (files 38188, 38238: no download URL), while the
   same section's inline links (38245, 38246) work. Use the inline links.
10. **Hidden module items:** id gaps under each Lab SubHeader (19989–90, 19993–97, 20000–01,
    20005–07, 20012–14) and in Module 5 (19947, 19950–52): unpublished items, likely the per-lab sheet
    and presentation entries the earlier scan saw.
11. **"Individually or in a group" vs group work:** all six lab assignments allow working alone; the
    Assessments page and 9.1 say groups of 3–4. Lab 1 alone is graded individually and uses another
    group set. The plan's `t-group` note ("Labs 2 to 6 may not" be done alone) is not supported by the
    assignment text, and task `w39-book1` (book a Lab 1 session) asks for something that does not exist.
12. **Pre-knowledge:** 0.1 says one poll per each of the eight modules; there are seven (no Module 1).
13. **Dead support links:** 18 pages and discussions point at a forum in `canvas.ltu.se` course 23566.
14. **Midterm location "Zoom"** on the Homepage, while it is a Canvas quiz with a 24-hour window.
15. **Midterm Overview table:** Midterm 2 coverage typed as "Module 5.8".
